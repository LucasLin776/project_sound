# 数据与标注规范

## 每行一条完整录音

JSONL 示例，数值仅解释格式，不是参考录音的实际标注：

```json
{"recording_id":"trial_a_01","audio":"../raw/trial_a.wav","group_id":"independent_trial_a","split":"train","reviewed":true,"events":[{"start_s":12.3,"end_s":16.8}],"notes":"包含掉落、滚动、后续碰撞"}
```

| 字段 | 含义 |
| --- | --- |
| recording_id | 清单内唯一的录音 ID |
| audio | 原始音频路径，相对清单所在目录或绝对路径 |
| group_id | 同一独立试验/连续采集过程的分组；划分粒度按试验、采集批次或风机确定 |
| split | train、val、test；未划分时为 unassigned |
| reviewed | 人工核对整条录音及所有目标事件后才为 true |
| events | 所有目标声音区间；完整确认无目标时为空数组 |
| notes | 可选，用于试验条件、干扰类型、标注不确定性 |

区间是 `[start_s, end_s)`，不得超出录音或相互重叠。掉落和紧接着的滚动、碰撞可标成一个连续事件，多个分离事件分别标注。不要只挑最大峰值；应结合听音、波形和时频图核对。不可把整条有事件录音的所有窗口标成正例。

工具不会猜测原始参考录音的准确起止。`reference.jsonl` 设置 reviewed=false、split=unassigned，不参与训练。若边界或事件类别无法确认，暂不将整条设为已核对。

## 分组与评估

先按独立试验组分 train/val/test，再提取窗口。同一试验的重复录音、不同切片、同源增强样本必须放在同组、同一 split；若要衡量新风机迁移，应按风机整体留出。

检查器拒绝同一个 group_id、recording_id 或内容 SHA-256 出现在不同 split。对于内容不同、来源相同的切片或混音，它依赖你正确维护 group_id。

训练集与验证集都需要正负窗口，验证集还必须同时有完整正常录音和事件录音。正常背景不能全部来自静止状态。训练负例应覆盖运行机械噪声、风噪、刹车/启停、人员操作、其他金属撞击等实际易混淆情况。

默认任意正时长事件重叠的窗口标为 1；未重叠、但落在事件边界前后 0.2 秒缓冲区的窗口标为 -1，不参与监督拟合和窗口指标；其余已核对窗口标为 0。缓存保留所有窗口，整条录音阈值选择和评估仍计算这些模糊窗口，保持与实际检测时一致。这是可迭代的初始标注规则，不代表弱事件在窗口中一定可识别。

模型先用训练集拟合标准化和分类器，再按验证集整条录音 F1 选阈值；测试集只用于最终评估。输出窗口混淆矩阵、precision/recall/F1/AP，以及录音级混淆矩阵和 precision/recall/F1。重叠窗口不是独立试验，不能把窗口数量当成独立样本量。当前未实现事件级匹配指标或每小时误报率。

## 参考录音质量

原设备录音约 30.003 秒，44.1 kHz、单声道 PCM16；原始文件保持不变。此前检查发现约 1.589% 原始样本达到数字量程边界，14–15 秒内尤其严重。保留这条录音用于流程验证；新增现场数据时同时检查增益、过载、安装位置与采集链路。
